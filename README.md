# PostPocket — Facebook Photo Organizer

**One post. One folder. Every image together.**

A local-first Chrome/Edge (Manifest V3) extension that turns Facebook post images into a tidy, searchable, private library on your own computer. Built from the full product spec in `chatgpt-full-chat.md`.

No backend. No account. No analytics. No developer access to your images. No passwords, cookies or tokens requested — ever.

---

> **v2.2 — compliance path C.** Archive/folder/ZIP import is now a real, local-first workflow (headline use case). The Facebook floating widget remains a clearly manual companion. Hidden `+N` photos open a **visible** tab you can close anytime; nothing is hidden or auto-downloaded. See `docs/ROADMAP.md`.

## Highlights

- **Floating download widget on every Facebook post** — one compact `⬇ N` icon. Click it for **Download all** or **Single image** (thumbnail picker). No need to open the popup.
- **Auto-scan, never auto-download** — the popup scans the current post as soon as it opens; nothing downloads until you press Save.
- **Clear thumbnails** — images are fetched inside the Facebook page (with your session) and shown as rounded 4:3 thumbnail cards.
- **Monochrome design** — pure black surfaces, white type, hairline borders, no color accents.
- One folder per post, naming templates, persistent queue, local library, ZIP/CSV/JSON export, side panel and full dashboard.

| Area | Feature |
| --- | --- |
| **Collect** | Single post, multiple loaded posts, post URL queue, local files/folder/ZIP import, Facebook archive folder import |
| **Preview** | Rounded thumbnail grid, individual/all selection, lightbox with prev/next, naming preview |
| **Folders** | One folder per post, naming templates, presets, prefixes, organize by source/month/year/topic |
| **Queue** | Persistent jobs (survive Chrome restart), pause, resume, cancel, retry failed, progress |
| **Library** | IndexedDB index, search, filters, sort, favorites, tags, rename, recycle bin, statistics |
| **Duplicates** | SHA-256 content hashes computed locally |
| **Export** | One ZIP, per-post ZIP, real nested folders, `post-info.json`, `README.txt`, `post-index.csv`, backup/restore |
| **UI modes** | Toolbar popup, Chrome side panel, full-page dashboard |
| **Settings** | 11 fully local settings modules |

## Install / update

```bash
npm install     # first time only
npm run build   # rebuilds dist/ after any UI change
```

Then:

1. `chrome://extensions` → Developer mode → **Load unpacked** → select `C:\laragon\www\facepostdownloader`
2. On the PostPocket card, make sure **Site access** is set to **On all sites** (or at least allow `facebook.com`)
3. Reload your Facebook tab
4. You'll see the small `⬇ N` widget on posts that contain images

**If you change any source file, run `npm run build` and click the Reload ↻ button on the extension card.**

## Usage

**Fastest:** on a Facebook post, click the floating `⬇ N` icon → **Download all** or **Single image** → click a thumbnail.

**From the popup:** click the toolbar icon — it auto-scans the page and shows any posts with images; pick one, select thumbnails, then **Save selected**. Nothing downloads automatically.

**Full workspace:** the popup's `↗` button opens the dashboard with Collect, Library, Queue, Settings and About.

Naming example:

```
Downloads/
└── PostPocket/
    └── Group_Lok_Sewa_Exam_Preparation/
        └── 2026-11-18_Old_question_set_subjective_questions/
            ├── 01_old_question_set_subjective_question.jpg
            ├── 02_old_question_set_subjective_question.jpg
            └── post-info.json
```

## Tech stack / architecture

- **UI:** React 19 + TypeScript + Vite, one shared design-token stylesheet (`src/ui/styles.css`) with CSS variables for light/dark themes.
- **Content script:** vanilla JS (`src/content/content.js`) — reads the page and injects the floating widget.
- **Background:** vanilla JS service worker with persistent queue, IndexedDB library and ZIP engine.
- **No framework in the page or worker** by design — MV3 content scripts and service workers are plain JS.

```
src/
├── shared/       utils, settings, naming, db, zip, scanner
├── content/      content.js (page bridge + floating widget)
├── background/   service-worker.js, queue.js, exports.js
├── ui/           styles.css (design tokens — imported by React)
└── ui-react/     React UI: config, types, api, views, components, styles
dist/             built React pages (generated by npm run build)
```

All user-facing strings, defaults, nav items, groups and message names live in `src/ui-react/lib/config.ts` and `lib/demo.ts` — nothing is scattered/hardcoded in views.

## Guidelines & safety

- Reads **only** the page you are viewing. No crawling, no background indexing.
- Local files, folders, ZIPs and Facebook data-export folders are imported and stored entirely on this device.
- One post at a time, started manually. Downloads run one at a time by default, with an optional parallel-tasks setting and gentle staggering.
- Uses your normal browser session; never asks for a password, cookie, token or login code.
- Does not include the `chrome.cookies` permission and has no stealth/anti-detection code. The photo viewer is read by the declared content script on the tab you explicitly open via the `+N` tile.
- Respects access controls: if you cannot see an image, it cannot save it.
- No analytics, telemetry, remote JavaScript, cloud sync or developer-side storage.

See `PRIVACY.md` and `STORE_LISTING.md`.
